# 抢球策略日志字段与事件说明

## 文件与配置

- 运行日志：平台可执行目录中的 `StrategyNew2V2_observability_team0.log` 和 `StrategyNew2V2_observability_team1.log`。
- 坐标口径：所有鱼和球状态均为 `RightToLeft()` 后的归一化左侧视图，即我方进攻/防守方向按主线逻辑统一处理。
- Debug：每 50 个有效决策周期记录两条 `SNAPSHOT`（每鱼一条），并保留异常事件。
- Release：编译时移除 `SNAPSHOT`，只保留版本、开局、换边和异常事件。
- 所有写盘均有异常保护，日志失败不得中断策略决策。

## SNAPSHOT 字段

`SNAPSHOT` 行为制表符分隔，共 17 列：

| 列 | 字段 | 含义 |
| ---: | --- | --- |
| 1 | recordType | 固定为 `SNAPSHOT` |
| 2 | cycle | 观测层单局有效决策周期 |
| 3 | phase | `FIRST_HALF`、`HALFTIME_TRANSITION` 或 `SECOND_HALF` |
| 4 | teamId | 本周期平台队伍 ID |
| 5-6 | myScore / opponentScore | 当前我方/对手比分 |
| 7 | fishId | 鱼编号 0 或 1 |
| 8-9 | xMm / zMm | 归一化坐标，单位毫米 |
| 10 | bodyDirectionRad | 鱼体朝向，单位弧度 |
| 11 | velocityMmPs | 线速度，单位毫米/秒 |
| 12 | angularVelocityRadPs | 角速度，单位弧度/秒 |
| 13 | targetBall | 当前周期明确分配的目标球，`-1` 表示无有效目标 |
| 14 | strategyBranch | 稳定分支名，如 `NORMAL`、`FINAL`、`GOAL_AREA_PRIORITY` |
| 15-16 | VCode / TCode | 最终返回平台的档位，均已限制在 0-14 |
| 17 | reason | 旧策略分支产生的可读原因摘要，最长 500 字符 |

## 稳定事件名

| 事件 | 触发条件 |
| --- | --- |
| `VERSION` | 观测实例开始，记录日志版本和坐标口径 |
| `MATCH_START` | 识别到新比赛 |
| `SIDE_SWAP` | `teamId` 发生换边变化 |
| `DECISION_EXCEPTION` | `GetDecision` 捕获真实异常 |
| `NO_TARGET` | 两鱼连续 100 周期均无有效目标 |
| `TEAMMATE_TARGET_CONFLICT` | 两鱼连续 30 周期选择同一有效目标球 |
| `SCORED_BALL_TARGET` | 某鱼连续 5 周期追踪已得分球 |
| `PROLONGED_LOW_SPEED` | 有前进命令但速度低于 20 mm/s 持续 120 周期 |
| `PROLONGED_SPIN` | 低线速度、高角速度且转向持续 120 周期 |
| `REPEATED_WALL_CONTACT` | 靠近场地边界持续 60 周期 |
| `GOAL_BLOCKED` | 堵门状态连续 5 周期成立 |
| `BOUNDARY_STALEMATE` | 鱼靠近边界且有动作命令但持续低速 60 周期 |
| `TARGET_THRASHING` | 120 周期窗口中目标变化不少于 8 次 |

状态型异常均写入 `state=ENTER` 和 `state=EXIT`，便于确认进入、持续和恢复。
