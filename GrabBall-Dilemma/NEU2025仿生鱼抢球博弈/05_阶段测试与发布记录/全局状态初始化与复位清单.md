# 全局状态初始化与复位清单

## 1. 唯一复位入口

- 每次 `GetDecisionCore()` 首先调用 `GlobalVar.PrepareForDecision(RemainingCycles)`。
- 第一次调用，或 `RemainingCycles` 相对上一帧向上跳变超过 100 拍时，判定为新局。
- 新局只通过 `ResetMatchState()` 清理比赛状态，并记录 `MATCH_STATE_RESET`。
- 半场交换的剩余周期不会向上跳变，因此不会误触发整局复位。
- `DecisionSync` 保护共享静态状态，避免同一 AppDomain 内并发调用互相覆盖。

## 2. 复位分组

| 状态组 | 代表成员 | 初始值/复位方式 | 后续复位时机 |
| --- | --- | --- | --- |
| 周期与阶段 | `Paishu`、`Stage`、`YStage`、`final`、`CQstage`、`DStage` | 0 | 新局；局内按状态机退出条件 |
| 当前帧/对象引用 | `MyTeamLast`、`decisions`、`po`、`myFish` | `null` 或清空 | 新局；当前帧引用每拍覆盖 |
| 比分与半场备份 | `leftScore`、`rightScore`、`leftScoreCopy`、`rightScoreCopy`、`b0_l..b8_r` | 全 0 | 新局；2998/3000 拍备份/恢复 |
| 目标与分配 | `Bringing_BallID`、`willbring_ballid`、`SingleBringing_BallID`、`is_ball_choosed` | 目标 ID 为 -1，其余清零 | 新局；目标得分、丢失、冲突或分支退出 |
| 禁区/带球/边界状态机 | `lanqiuFlag`、`Rescue_boundary_*`、`Dribbleboundary_*`、`enter_gate_stage` | 数组清零；历史哨兵值恢复为 100 | 新局；各动作完成/超时/目标丢失 |
| 锁死与恢复 | `deadjudge`、`deadtime*`、`locktime*`、`dead`、`locked`、`youlockme` | 0 | 新局；脱困或检测条件消失 |
| 对手历史采样 | `enemyx*`、`enemyz*`、`enemydirection*`、`recordfishz` | 历史数组清零；`recordfishz` 为 500 | 新局；循环采样覆盖 |
| 偷袭/末段状态 | `Unarmed*`、`finallanqiu`、`escape_lanqiu`、`last2min_*` | 标志 0；方向 `{1,-1}` | 新局；对应阶段退出 |
| 末段禁区入口防抖 | `lateGoalAreaPriorityEntryCounter`、`lateGoalAreaPriorityActive` | 计数 0、未激活 | 新局；禁区无有效球时立即清零 |
| 边界挑球 | `stalemate_timer`、`flick_ball_stage`、`flick_ball_cooldown` | 0 | 新局；条件消失、挑球完成、冷却递减 |
| 对手绕行 | `detour_stage`、`detour_target_opp` | 阶段 0、目标 -1 | 新局；接近球、目标丢失或动作退出 |
| 误差/统计缓存 | `error_record`、`errorflag`、`jimiao`、`count`、`Delay`、`abc` | 清零 | 新局；循环采样覆盖 |

## 3. 不应在新局清零的稳定数据

- 场地几何、鱼体尺寸、速度表和转向表。
- `BaseAction` 单例和 `GlobalVar` 单例引用。
- 新功能命名阈值，如 `StalemateTriggerCycles`、`FlickCooldownCycles`。
- `matchSequence` 诊断计数；不同策略 AppDomain 可各自从 1 开始，不能据此要求左右队共享序号。

## 4. 验证标准

连续两局不重启服务端与测试进程，必须观察到两次 `MATCH_STATE_RESET`，且事件中的 `final=0`、`goalBlocked=0`、`target0=-1`、`target1=-1`、`detour0=0`、`flick0=0`。第二局不得出现上一局目标、计时器或状态机残留。
