# 小黄鱼 2D 仿真项目工作与测试分阶段执行计划

## 1. 使用方法

- 本文档是项目推进的唯一阶段清单。工作完成后把 `- [ ]` 改为 `- [x]`。
- 每一阶段必须同时完成“工作内容”和“测试内容”，并满足“阶段出口”后才能进入下一阶段。
- 每次策略修改只解决一个明确问题。没有基线、测试记录和可回退 DLL 的修改不得进入主线。
- 抢球博弈是当前主线；水中搬运、生存挑战、花样游泳三个项目在抢球博弈完成可提交版本后推进。
- 本计划中的局数是默认最低值；若正式规则、赛程或仿真平台能力不同，以正式规则为准并在测试记录中说明。

## 2. 最终目标与交付判定

### 2.1 最终目标

- [ ] 同学能够在独立环境中打开抢球博弈工程、修改策略、编译出 x86/.NET Framework 3.5 的 DLL。
- [ ] 同学能够在仿真平台加载自研 DLL 与 `NEU222.dll`，按统一流程进行可重复的对局测试。
- [ ] 最终提交 DLL 在双方位置互换后仍能稳定运行，并在有效样本中整体优于 `NEU222.dll`。

### 2.2 默认发布门槛

- [ ] Release 配置编译成功，0 个错误；新增警告已解释或消除。
- [ ] DLL 可加载，队名正确，整场无异常、无卡死、无数组越界或无效档位。
- [ ] 对 `NEU222.dll` 至少完成 30 场有效对局，左右队各不少于 15 场。
- [ ] 总胜率不低于 60%，不败率不低于 75%。
- [ ] 左队与右队两个分组的平均净胜分均大于 0，不允许只依赖单侧优势。
- [ ] 关键场景回归全部通过：开局、半场交换、角落球、禁区球、堵门、僵持、末段清球。
- [ ] 最终 DLL、源码快照、哈希、编译日志、测试记录和说明文档一致且可追溯。

## 3. 项目现状基线

- 抢球博弈主工程：`2024-RST-水中机器人仿真组（2D）11.12/2D仿真平台/URWPGSim2D/Strategy666/StrategyNew2V2/StrategyNew2V2.csproj`。
- 新手隔离工程：`新手试炼/BeginnerStrategy/BeginnerStrategy.csproj`，用于教学、试改和独立编译。
- 仿真运行目录：`新手试炼/SimServer`；当前目录清单中未发现正常命名的 `URWPGSim2DServer.exe`，只有隐藏的 `._cache_URWPGSim2DServer.exe`，环境阶段必须先确认可执行文件已完整落盘。
- 对标程序：`新手试炼/SimServer/StrategyCache/NEU222.dll`，其他目录也有副本，测试时必须固定一份基准并记录 SHA-256。
- 新增黑盒强对手：`NEU222pro基线/冻结产物/NEU222pro.dll`，SHA-256 `06ABB28B771C05485264507ED0C593DDF6BD511C2999DDD45F36E37B9FC603D5`；不得反编译、复制或派生其实现。
- 抢球博弈代码入口：`Strategy.GetDecision(Mission mission, int teamId)`；输出为每条鱼的 `Decision.VCode` 和 `Decision.TCode`。
- 抢球博弈核心模块：`Strategy.cs`、`BaseAction.cs`、`GlobalVar.cs`、`Compute.cs`、`DebugRecord.cs`、`MyFishRobot.cs`、`Point2D.cs`。
- 另三个策略工程：`StrategyBallMoving`、`StrategyFightForLive`、`StrategySynchronisedSwimming`，目前基本为官方模板。
